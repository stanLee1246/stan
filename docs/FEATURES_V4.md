# V0.4 数据科学案例借鉴与项目增强指南

日期：2026-10-15。项目继续使用 Vue 3、FastAPI 与本地 MySQL；没有新增付费服务、运行时外部 API、Python/Node 依赖或数据库迁移。学生数据和原有学校、问卷、决策记录保留。

## 一、参考了什么，具体改了什么

本次实际读取七组官方或维护者 GitHub 资料：Datawhale、Streamlit、Plotly Dash、Apache Superset、Metabase、Evidently、scikit-learn，均返回 HTTP 200。部分官网被云出站代理403拒绝；没有宣称实际运行第三方演示或实时审阅受限页面。逐项链接、核验事实与访问边界见 [调研清单](REFERENCE_RESEARCH_V4.md)。

| 借鉴点 | 本项目的实际落地 |
| --- | --- |
| Datawhale：观察→清洗→建模→评估 | 从已实现的ETL/仓库继续补充可运行推荐方法对照，明确何时才能评价真实效果 |
| Streamlit：输入、结果、表格、导出连贯 | 两个新页面都有画像依据、范围、空状态、解释与报告导出；继续使用Vue |
| Dash / Metabase：筛选与图表联动、钻取 | 数据洞察点击路径/城市/月份联动全部图表，点击技能查看同范围机会 |
| Superset：统一维度与指标口径 | 共享路径、城市、专业、发布日期、数据类型，明确未知与过期公告范围 |
| Evidently：逐项质量证据 | 六类公告字段的已知/缺失/覆盖率，保留分母，并随统计CSV导出 |
| scikit-learn：TF-IDF及真实标签评价约束 | 独立实现smooth-IDF、sublinear-TF、L2余弦，与结构化规则对照；无真实标注不填准确率 |

这是业务与方法借鉴，没有搬用第三方网站资产、职业数据库或整套毕设代码。算法标准库实现的中文双字片段处理、参数和范围都显式记录，不能当作语义理解模型。

## 二、从图表钻取到原始机会

入口：**数据洞察 `/analytics`**。

1. 切换公开或模拟范围，选择专业、城市、路径和发布日期。
2. 点击路径环图、城市条形图或月份折线上的一项，相应条件会联动到全部统计；堆叠柱可同时选城市与路径。页面按钮提供相同的键盘操作。
3. 点击技能矩形或城市×技能热力格，进入发展机会列表，携带相同来源类型、专业、城市、路径和日期，以及精确技能条件。
4. 机会列表自动包含过期项，以便与图表统计范围核对。默认检索仍排除已确认过期；日期筛选排除未知发布日期，未知城市不冒充具体城市。
5. 使用“复制当前分析链接”分享范围；浏览器无法自动复制时会显示可选中的只读链接。刷新、历史导航恢复查询条件，未提交表单不改变已应用分析的范围。
6. 使用“清除联动筛选”返回全范围。各图依然保留Top N说明与表格/CSV入口；机会列表最多显示200条。

链接只包含筛选条件，不包含登录令牌、画像或问卷。技能钻取示例参数为 `data_kind=demo&skill=SQL&city=长沙&path=employment&include_expired=true`。结构化技能匹配会统一别名并在每条公告内去重，搜索文本关键词与精确技能条件分别处理。

## 三、把“字段缺了什么”说清楚

图表之前新增 **公告字段完整性**：城市、结构化技能、专业条件、最低学历、发布日期、截止日期六行，逐项显示已知数量、缺失数量和当前筛选分母。

```text
字段覆盖率 = 当前范围该字段已知公告数 / 当前范围全部最新公告数
```

没有公告时覆盖率为未知，不显示虚假的0%或100%。字段已知不代表事实正确；页面不把六项平均成一个“质量总分”，也不把格式校验通过当作推荐准确。需要人工核对的资格条数单独展示。统计CSV追加相同质量计数和分母，便于答辩核查。

后端契约：`GET /api/analytics` 返回原有图表数据及 `quality`；`GET /api/opportunities` 追加 `skill`、`major`、`start_date`、`end_date`，支持与图表相同的标准化条件。新的筛选查询没有改写机会记录。

## 四、技能成长：从线索到一份小成果

入口：登录学生 → **技能成长 `/skills`**。先保存个人画像。

系统从当前意向的最新机会中，排除明确过期、已知专业不符、学历不足记录；城市默认是偏好，只有主动勾选时才限制范围。未知资格保留待核对。

页面最多展示六项技能线索，先列尚未自报项，再按机会提及次数排序；学生自选1–3项，生成两周练习、成果要求、检查方法和官方学习入口。每项提供对应机会标题、版本、原文链接和截止日期，最多展示12条证据并明示截断。

技能频次分母是**已列出技能要求的合格条目**，与图表全公告分母不同，页面分别说明。整个技能画像为空时，只提供探索线索，不认定缺乏能力；“尚未自报”也不等于不会。

选择保留在当前页面，可以导出带来源和第14天复盘的Markdown、打印计划，或把证据送入辅助决策追踪长期行动。完成练习后由学生自行把有依据的变化写入画像，不自动授予能力认证。说明与接口见 [技能路线设计](SKILL_ROADMAP.md)。

## 五、推荐方法对照：可解释的算法实验

入口：登录学生 → **推荐方法对照 `/experiments`** → 运行对照。

| 项目 | 结构化规则 | TF-IDF词面基线 |
| --- | --- | --- |
| 查询依据 | 自报技能、城市偏好、专业条件 | 自报技能、项目经历文本 |
| 机会依据 | 技能/城市/专业结构字段 | 标题、技能、描述前4000字 |
| 分数 | 0–100关联分，至少两项有效观测 | 0–1余弦，无向量为未知、无共同词为0 |
| 共同前提 | 同一画像、同一数据类型、最新版本、相同资格检查、最多100条合格候选 | 同左 |
| 结果解释 | 分项值、已知权重、缺失维度 | 共同词片段、TF、IDF、贡献和尾部贡献 |

每个发展路径独立建词表、计算IDF和排序，并列同名次。无正相似度不排文本名次；不同路径不合成“人生排名”，两种不同量纲的分数也不相加。

报告保留画像版本、查询指纹、候选语料指纹、实际机会内容、参数与范围，可导出JSON和Markdown。实验只读，不覆盖原决策与画像，也不读取问卷、其他学生画像或心理角色。

这是可运行的**算法对照**。当前没有经授权并独立标注的学生—机会相关性真值，因此准确率为未知，不伪造Precision、Recall、NDCG或“提升百分比”。单次计算耗时包含数据库访问，只描述本次运行，不当作严谨性能基准。公式、中文双字处理与测试详见 [方法设计](TEXT_EXPERIMENTS.md)。

## 六、更新和建议演示路线

先停止旧服务，更新源码，保留电脑上的 `backend/.env`、虚拟环境和MySQL数据库。在项目目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup-local.ps1 -Demo
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

本版本仍使用迁移头 `0005`。如果此前已初始化且依赖完整，更新源码后重启即可；运行setup可重新核对依赖、构建与幂等初始化。日常只需start脚本。参考网站的技术栈没有成为本项目新的部署要求。

答辩建议顺序：使用路线 → 学校来源 → 画像与伙伴 → 图表联动及质量分母 → 原始机会 → 辅助决策取舍 → 技能计划 → 算法对照报告 → 管理员ETL和仓库。模拟数据始终显式标记，不能拿来证明真实推荐有效。
