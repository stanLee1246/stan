# 从公告证据到两周技能尝试

学生侧入口为 **技能成长 `/skills`**。管理员的数据加工全景展示技能共现与聚合口径，学生可在这个入口把自己当前意向机会的技能线索转成具体练习，再回到画像和辅助决策。

## 业务流程

1. 保存自己的个人画像，至少明确专业、学历和发展意向。
2. 选择公开机会或模拟演示。默认城市只作偏好，可主动勾选“只看偏好城市”。
3. 查看本次符合口径的条目数、技能已知/未知分母与排除原因。
4. 从最多6项技能线索里自主选择1–3项。尚未填写技能时，系统只提供探索线索，不推断能力差距。
5. 阅读真实关联的机会版本、原文和技能练习建议，确定一个可展示成果与验证办法。
6. 导出 Markdown 计划或打印，在两周内完成小样例、应用、反馈与复盘。
7. 将能举证的变化更新到个人画像，回到机会探索或辅助决策。正式行动进度可在辅助决策中保存与追踪。

## 统计与优先顺序

`GET /api/skills/roadmap?data_kind=public|demo&preferred_city_only=false`

需要登录，只读取当前账户的最新有效画像。服务不接受任意用户编号，也不返回其他账户的资料。

- 按数据类型、来源 URL 和来源记录编号只取最新机会版本。
- 排除不在画像发展意向内、明确过期、已知专业不匹配、已知学历不足的条目。
- 缺少专业、学历或截止时间时保留未知，同时计入“待核对”，不承诺报名资格。
- 默认不按城市排除；主动勾选后按规范化城市匹配，并排除城市未知条目。没有城市偏好时拒绝开启城市筛选。
- 每条机会内部先规范化技能别名、去空白和去重。一个条目重复写 `SQL/sql/SQL` 只计一次。
- 技能占比的分母为**符合本次口径且列出至少一项技能要求的条目数**，同时展示全部符合口径条目和技能要求未知条目数。占比不能解释成完整市场需求或学生胜任概率。
- 已自报技能时，先展示尚未自报的技能，再按提及频次降序、名称排序；最多6项。尚未自报只代表标签未填写，不代表不会。整个技能栏为空时，每项状态均为未知，仅按频次提供探索线索。
- 每项最多展示12条实际机会证据，同时明确完整提及数和证据截断状态。证据包含机会编号、版本、标题、路径、城市、截止日、来源 URL 和核对提示。
- 各排除原因可能重叠，不可将原因数相加作为排除条目数。

## 学习资源与边界

Python、SQL、MySQL、pandas、Spark、ECharts、Vue、Excel、Java 配置对应技术发布者的官方文档入口，并提供项目练习、可保存成果和检查办法。SQL 示例教学入口来自 PostgreSQL 官方文档，本地练习使用项目 MySQL，页面明确提醒语法差异。

未配置的技能名使用通用练习模板，请学生向老师或领域内人员先确认术语与可靠资料；不生成虚构课程、证书或培训承诺。两周用于安排一次可调整的小尝试，不承诺从零精通。

该页面没有新增个人数据库表。选择只保留在当前页面，导出文件由学生自行保存，不自动修改画像。导出包含当次数据类型、日期、画像版本、统计分母、练习和原文证据；不含密码或其他学生信息。切换公开/模拟模式或城市范围时会丢弃旧响应，避免范围混淆。公开数据为空时明确显示空状态，不混入模拟记录。

## 验收要点

- 未登录不能调用；没有自己的画像时提示填写，不借用他人画像。
- 新版本替代旧版本；不符路径、专业、学历及过期条目不进入学习统计。
- 技能别名去重、未知要求与分母正确，城市别名筛选一致。
- 空技能画像不出现零能力分数或“全部不会”的结论。
- 公开与模拟数据完全分开；空的公开范围不制造真实市场趋势。
- 页面可选择1–3项，导出计划包含成果、检查办法和实际原文；手机布局和键盘焦点可用。
